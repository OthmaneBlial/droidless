02 / THE ENGINE

⚙️ Follow the bytecode.

Tiny workspace.
Big responsibility.

DROIDLESS owns the execution path. Three crates turn an APK into guest objects, a View tree and native controls.

  1. 01 / UNPACK THE IDEAS
    📦

    Read the APK

    Parse ZIP contents, binary XML, resources and DEX modules without extracting guest files.

    droidless-formats
  2. 02 / DO THE WORK
    🧠

    Run its code

    Interpret registers, objects, method calls, dispatch and exception handlers in Rust.

    droidless-runtime
  3. 03 / BUILD THE BRIDGE
    🌉

    Translate APIs

    Supported Activity, resource, layout and View calls produce a desktop View tree.

    Android compatibility
  4. 04 / HELLO, DESKTOP
    🪟

    Go native

    AppKit renders controls. Mouse, text and key events return to the app’s own bytecode.

    droidless / macOS

↩ Every supported click goes back through the guest runtime. Current execution is interpreted; no JIT or Android engine is embedded.

cd droidless
cargo build --release --locked

🔬 The current boundary

Experimental, with a limited API subset. AndroidX, Compose, native libraries, general file APIs, main/native-bridge waits, worker Looper delivery, general Java timers and networking are future work. Current source grants bounded SharedPreferences storage and a fixed virtual /proc/self/cmdline response. Linux has an unverified headless path and no native GUI. Use trusted APKs; this prototype is not a security sandbox.
