DROIDLESS parses Android packages, executes their DEX bytecode in its own register machine, and maps a small Android framework subset to native macOS UI.

01

What actually runs

A real APK.
A real result.

The independently released KasCalc v1.0 APK runs without rewriting or repackaging its application bytecode. Native button clicks return through the Rust interpreter to the APK’s own handlers.

02

Inside the runtime

Bytecode in.
Native views out.

Application logic runs in DROIDLESS’s interpreter. Android framework calls cross a narrow compatibility bridge; clicks cross back.

  1. 01 / LOAD

    APK & formats

    Read ZIP contents, binary XML, compiled resources and DEX modules.

    droidless-formats
  2. 02 / EXECUTE

    Register machine

    Run application methods with registers, object handles, dispatch and exception handlers.

    droidless-runtime
  3. 03 / TRANSLATE

    Framework bridge

    Resolve supported Activity, resource, layout and View calls into a desktop view tree.

    framework.rs · ui.rs
  4. 04 / RENDER

    Native macOS

    Render AppKit controls and route input events back into the guest application.

    droidless (CLI)

No Android runtime or emulator in this execution path. No JIT: the current engine is an interpreter.

03

Try the prototype

Start with
the source.

Build locally with Rust. Native rendering also needs the macOS developer tools. An Android SDK is only needed to rebuild the authored test fixtures.

Commands, architecture & limitations →
BUILD / macOS
git clone https://github.com/OthmaneBlial/droidless.git
cd droidless
cargo build --release --locked
sh tools/fetch-kascalc.sh
target/release/droidless run artifacts/apks/KasCalc.apk

Linux has a headless code path; its build is not yet verified.

The current boundary

Modern AndroidX and Compose apps, JNI/native libraries, services, storage and networking are outside this prototype’s supported scope. Unsupported calls report errors.
