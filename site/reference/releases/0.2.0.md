# 0.2.0 — notes, photos and native views

DROIDLESS now goes beyond the calculator preview: original public APKs save and
reopen notes, navigate between screens and browse selected-folder images through
its own Rust interpreter and native macOS View bridge. This is an experimental
macOS ARM64 release with a limited Android API profile.

## Public app evidence

- **Notepad 1.0.0:** headless two-note save/edit/restart, original Delete/Undo,
  drawer navigation and folder create/rename/delete. The original folder-delete
  dialog shows its title, message and buttons; Cancel retains the row, confirmation
  removes it, and restart/Back preserve both exact notes. Earlier native AppKit
  checks verified mouse row selection, keyboard title/body edits, Escape save and
  fresh-process restoration. Physical public folder/dialog input remains unverified.
- **SwpieView 1.3.2:** earlier native folder chooser, JPEG/PNG/WebP thumbnails,
  full-screen viewing, tap visibility and Escape back. Current host replay verifies
  original swipes, bounds, visibility, Parcelable reconstruction and Back. Native
  drag input, GIF animation and usable slideshow remain unproven.
- **Simple Calculator 1.0:** earlier native addition/multiplication/division and
  seven current headless arithmetic/input cases. KasCalc retains ten regression
  scenarios; it is not the featured demo or included in the archive.

All public APKs are unmodified and hash-pinned. They are fetched from upstream,
never redistributed in this release. Authored fixtures test runtime contracts;
they do not establish broad APK compatibility.

## Runtime additions since 0.1.0

Same-APK navigation and activity results; Bundle and real guest Parcelable
transport; isolated preferences and the Notepad SQLite path; collections and
reflection; retained exceptions; weak references and GC; Handler/Looper,
Timer, deferred workers and Futures; image decoding, native grids and read-only
document grants; focus, guest gestures, themed resources, modal panels,
foreground/clipping behavior, host-font metrics and UTF-16 ellipsis metadata.

Bounded private FileInputStream reads now use the existing package capability.
The virtual external directory stays inside that package. Input channels share
position and close state with their stream, including wide positions and EOF.
Reads snapshot at most 64 MiB. Live descriptors, output, transfer/mapping/locking
and general file access remain unsupported. Notepad backup reaches its input
channel and stops at FileOutputStream; missing-file restore stops at Toast.
Neither backup nor restore is claimed complete.

## Download and local validation

The macOS ARM64 tarball contains the CLI, Apache-2.0 license, five authored APKs
(Counter, Intents, Preferences, Scheduling and Images), three SHA-256-checking
public APK fetch helpers, README and RELEASE.json provenance. SHA256SUMS verifies
the archive; RELEASE.json records the executable hash and source revision.
No Apple developer signature or notarization is provided.

Local CI: 147 Rust tests, formatting/checks, warning-free Clippy, optimized builds,
4,096 seeded parser mutations and five native component checks. The full public
replay certifies one unchanged optimized CLI hash. Packaging requires that matching
certificate, extracts into a clean directory and checks Counter callbacks,
navigation/Back, UTF-8 preferences and original Notepad save/restart.
GitHub Actions remain disabled.

```sh
shasum -a 256 -c SHA256SUMS
tar -xzf droidless-0.2.0-macos-arm64.tar.gz
cd droidless-0.2.0-macos-arm64
./droidless run --headless --ephemeral fixtures/counter.apk --click Increment
sh tools/fetch-notepad.sh
./droidless run --headless --size 390x844 --data-dir ./test-apps \
  --click "＋" --input "Hello, desktop" --back artifacts/apks/notepad-v1.0.0.apk
```

Normal execution needs no Android SDK, runtime or emulator. Source builds need
Rust 1.95.0 and Apple's Command Line Tools; SDK tools compile authored fixtures
only. Linux builds/native UI, broad AndroidX/Compose, JNI, networking, JIT and
games remain future work. Use trusted APKs; this is not an audited sandbox.
The 50% project target remains active and is not an API-coverage percentage.
